# 版本管理与中文提交说明

本文说明本仓库如何使用 Git 记录改动，以及如何撰写**中文提交说明**，便于协作与回溯。

## 仓库与分支

- **远端**：`origin` 指向 GitHub 上的同名仓库（推送前请确认身份与权限）。
- **实验分支**：STAR 闭集等相关开发可使用 `exp-*` 命名分支（例如 `exp-star-r1sgg-close-v1`），合并回主干前建议在 PR 中附上摘要。
- **数据与权重**：大目录（数据集、`checkpoints/`、`*.safetensors` 等）已由 `.gitignore` 忽略，勿强行提交；路径可在实验笔记 `experiments/*/notes.md` 中记录。

## 提交信息格式（推荐）

第一行：**类型(范围): 简短概括**（不超过约 50 字，使用中文）。

常用类型：

| 类型 | 含义 |
|------|------|
| `feat` | 新功能或新脚本 |
| `fix` | 缺陷修复 |
| `docs` | 仅文档、注释 |
| `refactor` | 重构，不改变对外行为 |
| `perf` | 性能优化 |
| `chore` | 构建、脚本、杂项 |
| `exp` | 实验性质快照（可复现记录） |

**范围**可选，用于模块名，例如：`feat(star闭集)`、`fix(grpo)`。

正文（可选，空一行后）：用条目列出要点，说明「改了什么、为什么」，便于日后查 `git log`。

示例：

```
feat(star闭集): 增加闭集预测评测脚本

- 对接 HF Dataset 与 preds.json，计算对象召回与三元组指标
- 与 star_closed_baseline_smallest_k 输出的 preds.json 格式一致
```

## 日常工作流（简要）

1. `git status` 确认仅包含预期文件。
2. `git diff` 自检逻辑与无关文件。
3. `git add` 选择性暂存；勿添加备份文件（如 `*.bak.*`，已被忽略）。
4. `git commit -m "标题" -m "正文"` 或使用编辑器写多行说明。
5. `git push origin <分支名>`。

## 与本机数据目录的关系

训练产出（例如 `/root/autodl-tmp/STAR/r1sgg_data/`）通常**不在**仓库内；请在实验笔记或 `experiments/` 下记录路径与命令，代码变更在本仓库中提交即可。
